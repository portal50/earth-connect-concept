# Candidate Use Cases — Unvalidated

1. **Café guest pet:** a Three.js café voluntarily displays a guest's portable cat with a disclosed source identity. The host can deny pets.
2. **Virtual gallery gift:** a visitor proposes a virtual artwork as a gift. The gallery owner explicitly accepts; no automatic transfer of copyright.
3. **Small planet visitor:** the host world has different gravity. A guest object is shown in a safe display mode unless supported behaviors are negotiated.
4. **Reality-anchored pet view:** a digital representation of a real cat can be viewed remotely, but simulated actions in another world cannot be recorded as physical facts.

## Why these scenarios may fail
- Existing scene embedding or asset import is already good enough.
- Creators do not want unmoderated foreign content.
- Maintaining compatibility is more expensive than its benefit.
- Most visitors do not own portable objects.
- Network effects do not exist at small scale.

No use case here implies validated willingness to pay.
